## 2026-11-26 statement audit

An independent statement audit of commit `67bedd4` (audit log: <https://github.com/0thernes/0thernes-research-archive/blob/main/docs/reviews/2026-11-26-statement-audit.md>) found the issues below. The Lean build passes, all 30 theorems use only `propext`, `Classical.choice` and `Quot.sound`, and Ubuntu CI run 45748401683 at that commit succeeded, including `lake check --paranoid` and `lake comparator`. The findings concern what the documents say the theorems mean. README.md, CLAIMS.md, LIMITATIONS.md, CITATION.cff (abstract), docs/statement-fidelity.md, docs/verification.md, docs/AI_DISCLOSURE.md, docs/adr/0001 and docs/ARCHITECTURE.md (Rule C7 note) were corrected in place. The frozen paper and the items listed below were not changed.

### Frozen paper (`paper/main.tex`, `dist/Donahue_2026_asmodensius_native.pdf`)

1. **Where:** `paper/main.tex` line 167, section "Exact Integer Conservation Laws", Rule C7 item. **What is wrong:** it states that each of the six face outflows is bounded by `floor(A/8)`. The transport code at the audited commit (`core/az_chem.c`, `spread()`) has no per-face 1/8 bound; it caps each species' total outflow per pass at `a/4` with a decreasing budget (`budget = (a / 4) << 16`, `left = a / 4`, `if (n > left) n = left`). **Correction:** Rule C7 as stated is the documented design rule in `docs/ARCHITECTURE.md`, not the implemented rule. **Affects a theorem statement:** no Lean statement changes, but it changes what `A22` is said to model.
2. **Where:** `paper/main.tex` line 181 (list of `Core.lean` contents) and line 205 (statement-fidelity table, row `A21`--`A22`). **What is wrong:** `A22` is mapped to `core/az_field.c` and described as the C7 bound of the engine. `core/az_field.c` only applies posted deltas. **Correction:** `A22` formalizes documented Rule C7 only; the corresponding code is `core/az_chem.c` `spread()`, which uses the `a/4` budget. **Affects a theorem statement:** no (fidelity mapping only).
3. **Where:** `paper/main.tex` abstract (line 50) and line 181. **What is wrong:** the 30 theorems are described as "core conservation, refusal, ABI, Philox-key, and VRAM-addressing theorems", including "D7 observer invariance", "GPU/CPU hash parity" and "prefetch transparency". Of the 30, 17 (`A04`..`A16`, `A18`..`A20`, `A25`) are definitional, constant or literal-arithmetic checks or restate their hypotheses; `A12` is `x = x`, `A18` assumes `stepGpu = stepCpu`, `A19` uses the identity function. **Correction:** 13 theorems (`A01`..`A03`, `A17`, `A21`..`A24`, `A26`..`A30`) are statements about the `Spec.lean` model; the rest are sanity checks. None of them verifies the C23, NASM or PTX code. **Affects a theorem statement:** no (description only).
4. **Where:** `paper/main.tex` line 186, section "Formal Verification and Statement-Fidelity Audit". **What is wrong:** "all 5 Windows-capable independent checkers" is followed by six names. **Correction:** six checkers ran locally (`lean` kernel, `leanchecker`, `leanchecker-paranoid`, `con-leche`, `con-ron`, `nanoda_bin`); `lean4lean`, `lake check --paranoid` and `lake comparator` run only in Ubuntu CI. **Affects a theorem statement:** no.
