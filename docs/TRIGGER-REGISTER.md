# Trigger register: deferred capabilities

Started 2026-11-17 (CONTINUE-BUILD.md, P21). Each row is a capability that is
deferred on purpose. It names the seam that exists today, the measurable event
that lets the work start, what must be shown when it lands, and the owner
decision it needs. A row is closed only with a run id and a command.

Every phase-2 substrate (DDR5 streaming tier, GPU, NPU) enters as a twin of the
CPU C reference: the same `az_state_hash` every tick, exact matter and energy,
an off switch, a measured gain, and an update of its row here. A result that is
not bit-exact may feed only outputs outside the hashed state (viewer, reports,
logs). Banned in every phase: the pagefile and any virtual RAM on NVMe (swap,
memory compression of state, disk-backed mapped memory, GPU oversubscription),
virtual machines, pretrained models.

The thresholds marked "proposed" are my numbers, not the owner's; he may
change them.
