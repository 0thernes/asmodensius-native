# Build Standard v1.2.0 Deviations (`DEVIATIONS.md`)

All deliberate deviations from Build Standard v1.2.0 or platform constraints are recorded transparently here.

| Item / Area | Standard Default | Asmodensius-Native Implementation | Justification |
|---|---|---|---|
| `scripts/Audit-Repo.ps1` & `scripts/audit-repo.sh` encoding & CWD | Upstream template contains three UTF-8 middle dots (`U+00B7`) on line 245, and PowerShell `Set-Location` does not update `[Environment]::CurrentDirectory` for `[IO.File]::OpenRead`. | Replaced the three middle dots in the Markdown summary string with ASCII `|` (`U+007C`) and set `[Environment]::CurrentDirectory = $Root` right after `Set-Location` while preserving 100% of check logic, TSV parsing, console output, and JSON output. `scripts/audit-repo.sh` retains its 3 POSIX `IFS` tab literals and is explicitly allowlisted in `tools/check_text.py` (`TAB_OK`). | Required by Project Law 14 (`tools/check_text.py` strict 7-bit ASCII) and accurate `Test-TextFile` resolution when invoked across drives on Windows PowerShell. |
| `docs/eval/TRACE.csv` size (`4,977,947` bytes) | `A24` (`hygiene`) caps single tracked files at `5,242,880` bytes (5 MiB). | `docs/eval/TRACE.csv` is `4,977,947` bytes (below 5 MiB, so `A24` passes cleanly). Retained unmodified per `AGENTS.md` owner-file preservation rule. | Owner evaluation trace record; never deleted or truncated. |
| `B02` (`lockfile`) with CMake | `Audit-Repo.ps1` `builtin:lockfile` checks for standard package-manager lockfiles when `CMakeLists.txt` is present. | The freestanding C23 core has zero external third-party runtime dependencies (`AZ_SRCS` compiles purely from `core/`), while Lean 4.35.0 pins `lean/lean-toolchain` and `lean/lake-manifest.json`. `B02` is documented honestly as `n/a` for third-party C package lockfiles in `repo.yaml`. | Zero external C or Python runtime dependencies exist to lock; Lean toolchain and manifest are pinned under `lean/`. |
| `A27` (`deploy-pages`) | GitHub Pages documentation/demo site. | Enabled in v1.2.0 via `.github/workflows/pages.yml` publishing the strict-CSP, zero-CDN, WCAG 2.2 AA documentation portal (`docs/index.html`) and interactive Lean 4.35.0 Proof Blueprint (`docs/blueprint.html`). Native C23/PTX simulation execution remains Windows-only per Law 10. | Publishes interactive formal verification explorer and archival metadata cleanly on GitHub Pages without faking native execution in the browser. |
| `B15` (`fuzzing`) & `B23`/`B25` (`TLA+`/`CBMC`) | Optional fuzzing and model-checking scanners. | Native code uses randomized property-based testing (`tests/test_*.c`), `ubsan_trap_build` with 6 planted traps, `cli_matrix_*` randomized split seeds, and 38 Pure Lean 4.35.0 declarations rather than AFL/libFuzzer/TLA+/CBMC. Marked `n/a` with rationale in `repo.yaml`. | Explicit verification boundary documented in `LIMITATIONS.md` and `docs/statement-fidelity.md`. |
| Windows vs Linux `lean4lean` & `bubblewrap` comparator | Local multi-checker replay vs full Ubuntu CI suite. | Six checkers run locally on Windows (`lean4` kernel, `leanchecker`, `leanchecker-paranoid`, `con-leche`, `con-ron`, `nanoda_bin`) because `lean4lean.exe` cannot parse Windows `.olean` path headers and `bubblewrap` is Linux-only. Ubuntu CI (`.github/workflows/ci.yml`) additionally runs `lean4lean` (`lake check --paranoid`), `lake comparator --config comparator.json --paranoid`, and `scripts/test_lean_negative.py --with-comparator`. | Platform limitation of `lean4lean` and `bwrap` on Windows; documented honestly in `results/lean4-multi-kernel.txt`. |
