# Build Standard v1.2.0 Deviations (`DEVIATIONS.md`)

All deliberate deviations from Build Standard v1.2.0 or platform constraints are recorded transparently here.

| Item / Area | Standard Default | Asmodensius-Native Implementation | Justification |
|---|---|---|---|
| `scripts/Audit-Repo.ps1` & `scripts/audit-repo.sh` encoding & CWD | Upstream template contains three UTF-8 middle dots (`U+00B7`) on line 245, and PowerShell `Set-Location` does not update `[Environment]::CurrentDirectory` for `[IO.File]::OpenRead`. | Replaced the three middle dots in the Markdown summary string with ASCII `|` (`U+007C`) and set `[Environment]::CurrentDirectory = $Root` right after `Set-Location` while preserving 100% of check logic, TSV parsing, console output, and JSON output. | Required by Project Law 14 (`build/work/scripts/check_text.py` strict 7-bit ASCII) and accurate `Test-TextFile` resolution when invoked across drives on Windows PowerShell. |
| `docs/eval/TRACE.csv` size (`4,977,947` bytes) | `A24` (`hygiene`) caps single tracked files at `5,242,880` bytes (5 MiB). | `docs/eval/TRACE.csv` is `4,977,947` bytes (below 5 MiB, so `A24` passes cleanly). Retained unmodified per `AGENTS.md` owner-file preservation rule. | Owner evaluation trace record; never deleted or truncated. |
| `B02` (`lockfile`) with CMake | `Audit-Repo.ps1` `builtin:lockfile` checks for standard package-manager lockfiles when `CMakeLists.txt` is present. | The freestanding C23 core has zero external third-party runtime dependencies (`AZ_SRCS` compiles purely from `core/`), while Lean 4.35.0 pins `lean/lean-toolchain` and `lean/lake-manifest.json`. `B02` is documented honestly as `n/a` for third-party C package lockfiles in `repo.yaml` (or accompanied by `requirements-tooling.txt` if Python tooling deps are introduced; currently tooling uses Python stdlib only). | Zero external C or Python runtime dependencies exist to lock; Lean toolchain and manifest are pinned under `lean/`. |
| `A27` (`deploy-pages`) | Optional GitHub Pages deployment workflow. | Marked `n/a` in `repo.yaml` (`deployed: false`). `Asmodensius-Native` is a native Windows bare-metal engine with local-only browser viewers (`demo/viewer_server.py`, `demo/live_server.py`) that require a live local `az_live.exe` process. | Cannot run bare-metal Windows `VirtualLock` / AVX-VNNI / CUDA PTX inside static GitHub Pages. |
| `B15` (`fuzzing`) & `B23`/`B25` (`TLA+`/`CBMC`) | Optional fuzzing and model-checking scanners. | Native code uses randomized property-based testing (`tests/test_*.c`), `ubsan_trap_build` with 6 planted traps, `cli_matrix_*` randomized split seeds, and 30 Pure Lean 4.35.0 theorems rather than AFL/libFuzzer/TLA+/CBMC. Marked `n/a` with rationale in `repo.yaml`. | Explicit verification boundary documented in `LIMITATIONS.md` and `docs/statement-fidelity.md`. |
| Windows vs Linux 6th Lean kernel (`lean4lean`) | Local multi-kernel replay runs all 6 kernels. | Local Windows replay runs 5 independent kernels (`lean4`, `leanchecker`, `leanchecker-paranoid`, `con-leche`, `con-ron`, `nanoda_bin`) because `lean4lean.exe` cannot parse Windows `.olean` path headers and `bubblewrap` is Linux-only. Full 6/6 kernels + `lake comparator` run in `.github/workflows/ci.yml` on `ubuntu-latest`. | Platform limitation of `lean4lean` and `bwrap` on Windows; documented honestly in `results/lean4-multi-kernel.txt`. |
